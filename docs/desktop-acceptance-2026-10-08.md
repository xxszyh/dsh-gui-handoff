## 自己复验

要求 Windows 交互桌面、Python 3.11+ 和 tkinter。不要用无人值守的 CI 桌面结果
代替本机验收。关闭的、锁定的或被其他窗口抢走的目标会导致失败。

~~~sh
python tools/gui-control/selftest.py --output .local/desktop-check
~~~

先显示倒计时，关闭提示取消；退出码 2 不会启动 fixture 或创建输出。提示异常
也会停止。倒计时正常结束才打开一次性窗口，检查全部完成后自动关闭。
输出目录已存在时直接报错，不显示提示、不覆盖旧结果。

正常报告 status=passed、input_checks=passed，检查项包括：

- MCP stdio 初始化和本次子进程 PID/窗口句柄身份。
- PNG 的三个 RGB 色块在正确的来源像素位置。
- 文本精确等于 GUI 验收 😀、换行、second line。
- Tab 后独立输入框精确等于 tab landed。
- 扫描码回车计数为 1，按钮点击计数为 1。

判据来自 fixture 的文本和计数，不凭截图宣布输入成功。fixture.png 保存完成后
的窗口截图。report.json、图片及其他本机产物保持在 .local，不进入安装包。
--capture-only 只查初始化、身份和截图，input_checks=not_run。

## 本轮修复及测试

直接运行早期自测绕过了 README 要求的倒计时。新增取消回归先验证失败，再接入
退出码检查。输入使用固定 150ms 等待也会在事件排队较慢时误报；模拟延迟的
fixture 复现了该问题。现在按实际状态等待，超时停止，不重发输入、不继续下一步。

截图读取先从 DC 解除位图，再调用 GetDIBits；失败清理 Win32 资源。read_region
整数 1 是 1 像素而非全图比例，图片及裁剪参数错误不会返回成功文本。

23 项 Python 检查、2 项 Node 插件/安装包检查通过。修复前后的两次本机完整桌面
自测均通过七项检查，修复后等待状态正确，窗口已关闭。自动化测试只用 mock 输入；
真实桌面自测需要显式运行，不放入普通 CI。

## 验收边界

本次覆盖参考驱动和一次性 Tk 控件，没有验收 Chromium/Electron、真实 IDE 的
编译运行流程、不同 DPI/多显示器布局或用户复现教程。这些需要对应的独立场景。
前台核对不能让 GetForegroundWindow 与 SendInput 变成一个原子操作。
主机调用其他输入工具时仍须执行提示并检查退出码；server 不自动替所有调用者弹窗。
