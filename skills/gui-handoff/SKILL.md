whenToUse: When the user says they do not know what to click, asks for a tutorial, says they cannot reproduce it themselves, or right after finishing a CLI task the user must repeat in a GUI.

# GUI 交接

## 要解决什么

命令行和图形界面做同一件事时，落差出现在**没被固化、也没被演示**的环节：
我能用 CLI 做，用户不知道 GUI 里点哪。

两条路，**默认走 B**：

| | 路径 B（默认） | 路径 A（降级） |
|---|---|---|
| 做法 | 我真的操作 GUI 走一遍 | 把步骤固化成配置文件 |
| 产出 | 带真截图的教程 | 配置文件 + 一键操作 |
| 用户学到 | **是** | 否 |
| 换机器可用 | **是** | 否（要重配） |
| 适用 | 默认 | B 走不通时 |

**A 的四个弊端**（这就是 B 优先的理由）：黑盒、换机器就废、用户学不会、
**覆盖不了没有配置接口的 GUI 操作**。

---

## 分诊

1. 先判断这件事**能不能真的走 GUI**（工具是否齐、目标程序能否被驱动）
2. 能 → **路径 B**
3. B 缺环 → 按降级链退：B1 全自动 → B2 半自动（用户操作我截图）→
   B3 录屏工具事后整理（Windows PSR 等）→ B4 纯文字
4. 用户明确只要"能一键跑" → 路径 A
5. **两条都做也不浪费**：A 让用户少记，B 让用户看懂

---

## 第 0 步：探测本机环境（每次都做，别跳）

**本 skill 不含任何绝对路径。所有位置必须现场探测。**

| 要探测 | 怎么探 |
|---|---|
| 目标程序在哪 | `Get-Command` / 查注册表 `App Paths` / 已知安装目录；**注意别名可能指向别的程序**（本机 `code` 命令实测指向 Cursor 而非 VS Code） |
| 编译器 / 解释器 | `Get-Command g++`、`python` 等，取绝对路径 |
| 屏幕与缩放 | DPI 感知进程读物理分辨率，不感知的读逻辑分辨率，**两者可能差 1.25/1.5/2 倍** |
| 截图放哪 | 建一个专用目录（**目录名用纯 ASCII**，见硬约束）。若已有策略/清理任务，沿用 |
| GUI 工具从哪来 | 见下方「工具」一节 |

**探测完把结论写进教程的「前置条件」**——用户要能核对。

## 路径 B 的执行流程

### 第 1 步：看清桌面

枚举顶层窗口（标题 / 句柄 / 进程 / 位置 / 是否最小化）。
**这是最可靠的信息源**——窗口标题能反映"工程是否打开""文件是否打开"，比读图可靠得多。

### 第 2 步：定位目标窗口

**用「启动前后快照求差集」定位新窗口，再按面积排除辅助窗口**（托盘小窗、2×2 隐藏窗）。

> ⚠️ **绝不要按标题子串匹配窗口。** 实践中因此踩过三次：
> 命中用户已打开的同名文件、命中文件资源管理器（标题也含目录名）、
> 命中标题相同的隐藏辅助窗口。
> **拿到句柄后就一直用句柄，不再做任何匹配。**

### 第 3 步：驱动

优先 **键盘快捷键**，不用坐标点击（理由见硬约束）。

- **文本输入**必须用 `SendInput` + `KEYEVENTF_UNICODE`，绕过中文 IME
- **组合键**默认发扫描码（`KEYEVENTF_SCANCODE`），Chromium/Electron 需要
- 键盘搞不定的才用坐标点击，且必须先验证坐标可靠

> **打字前先确认快捷键真的生效**：很多快捷键会弹出一个输入浮层；
> 若快捷键没生效，你接下来打进去的字会**直接写进当前编辑器、污染源码**。
> 安全的做法是**比对快捷键前后的截屏哈希**，画面没变就别打字。

### 第 4 步：逐步留证

每步后截图。**用不依赖视觉的地面真值判断成败**：

| 要判断 | 可靠判据 |
|---|---|
| 工程/文件是否打开 | **窗口标题** |
| 构建是否成功 | **产物文件是否存在 + 时间戳** |
| **程序是否真的运行了** | **程序输出、或调试器退出码**——产物存在只证明构建 |
| 视觉版面对不对 | 截图（给人看，**不作判据**） |

### 第 5 步：读图（需要看细节时）

整张大图直接发给视觉模型**必然读错小字**——模型内部会缩到约 1440 宽，
8px 的字缩成 5px。

**先裁剪出目标区域、放大 2 倍，再发给视觉模型。** 实测这能把中等字号的
文字从"完全读错"变成"稳定读对"。

### 第 6 步：出教程

见下方「交付物」。

## 硬约束

**全部来自真实踩坑，不是推测。换机器要复核。**

### 编码与路径（这一类最容易反复踩）

| 约束 | 现象 | 应对 |
|---|---|---|
| **某些链接器写不了中文路径** | MinGW `ld.exe` 在代码页 936 下无法把 `.exe` 写到含中文的绝对路径；报 `No such file or directory` 但目录明明存在 | 构建命令的 `-o` **用相对名**，配合工作目录；或整个工程放纯 ASCII 路径 |
| **某些调试器读不了 UTF-8 中文路径** | `gdb` 按 ANSI(936) 解释路径字节：喂 UTF-8 → `No such file or directory`；喂 GBK → `^done`；ASCII → `^done` | 工程放**纯 ASCII 路径**。用目录 junction 做别名即可，不必复制文件 |
| **命令行通过 ≠ GUI 通过** | PowerShell 传参时会自己做一次编码转换，**歪打正着**喂给 gdb 的正是它想要的编码 | 两条路径的参数编码不同，**必须分别实测** |
| **PowerShell 5.1 按 ANSI 读 `.ps1`** | 带中文的脚本报语法错、字符串被乱码截断 | `.ps1` 存 **UTF-8 带 BOM** |
| **Python 经管道调用时 stdout 非 UTF-8** | 中文 JSON 被编码坏掉 | 脚本开头 `sys.stdout.reconfigure(encoding="utf-8")` |
| **管道首行可能带 BOM** | 首条 JSON-RPC `initialize` 被判非法而**静默丢弃** | 服务端 `line.lstrip("\ufeff")` |
| **目录名尽量用纯 ASCII** | 中文路径会在工具链的各个角落以各种形式炸掉 | 新建的工作目录（截图、工程、别名）都用 ASCII |

### GUI 驱动

| 约束 | 现象 | 应对 |
|---|---|---|
| **中文 IME 污染注入的按键** | 注入 `typed by automation at` 会落盘成 `typed不要automation爱他`（`by`→`不要`） | `SendInput` + `KEYEVENTF_UNICODE`；控制键仍可能被吞 |
| **按标题匹配窗口极危险** | 见第 2 步 | 快照差集 + 面积过滤，之后只用句柄 |
| **Chromium/Electron 对扫描码敏感** | 只发虚拟键码可能完全无响应 | 默认发 `KEYEVENTF_SCANCODE` |
| **Electron 多窗口同进程，焦点可能切不过去** | 按键打到另一个窗口，现象是"按了没反应" | **按键前验证 `GetForegroundWindow() == 目标句柄`** |
| **编辑器会恢复上次会话** | 打开工程时文件本来就是开着的 | 不要假设"文件未打开"；教程写"若已打开则跳过" |
| **最小化窗口抓不到像素** | 抓到的只是标题栏 | 截图前先恢复窗口 |
| **打包应用的窗口句柄拿不到** | 启动进程与窗口不属同一 PID，返回句柄为 0 | 靠枚举窗口定位 |

### 视觉与验收

| 约束 | 现象 | 应对 |
|---|---|---|
| **视觉模型会一本正经地胡说** | 同一张图被多次描述成与事实不符的内容 | 关键判断用地面真值 |
| **但视觉模型说对了也不要因为"不可能"就驳回** | 它三次一致报告异常，我认定"不可能"并写成"模型胡说"的案例——**结果是我自己的编码器写错了** | **观测与先验冲突时，要验证的是先验** |
| **精确信息读不可靠** | 路径里的用户名数字连跑 6 次全读错 | **路径/数字/ID/版本号一律从系统取，不从截图读** |
| **手写 PNG 时 color type 2 必须逐像素交错** | 写成「R 平面+G 平面+B 平面」会让画面变成 **3 个水平压缩副本，周期恰好是宽度的 1/3** | 用 `px[0::3]=row[2::4]` 等切片赋值；**写完用合成图案逐像素自测** |
| **平铺检测不能用"相邻列差异"当基准** | 该基准由大片纯色决定，任何图都能"超标" | 正确判据：**周期 p 处的自差异 ÷ p±30 处的自差异 < 0.5** |
| **"产物出现"只证明构建，不证明运行** | 按产物生成判定"跑通"，实际调试器从未起来 | 判据必须覆盖到"程序真的跑了" |

### 环境与策略

| 约束 | 说明 |
|---|---|
| **沙箱行为是策略相关的，不是环境固有的** | 同一台机器上，"不能启动某类程序"的结论可能在文件策略放宽后**全部不成立**。**任何"做不到"的结论都必须标注当时的策略上下文** |
| **显示缩放会让尺寸读数据差整数倍** | DPI 感知进程读物理像素，不感知的读逻辑像素。两个工具报出不同尺寸时，**先想 DPI，别急着怀疑对方有 bug** |
| **配置文件的改动在进程运行时不生效** | 直接改配置文件后行为不变（内存缓存），必须走设置界面或重启 |

## 工作纪律

**这七条比技术细节更重要——全部是真实犯过的错。**

1. **单次实验不足以支撑结论。**
   一个"某方法解决了问题"的结论曾单次成功、复测 6 次全错。
   **必须复测多次才能写下。**

2. **不要相信中间层给出的原因归因。**
   插件报"思考 token 吃光预算"，真实原因是模型类型选错；
   现象是"连接超时"，真实原因是文生图模型卡 45 秒返回空。
   **自己构造对照实验**——同输入换变量，一次对比就能定位。

3. **报告矛盾结果时不要挑一个信。**
   出现互斥证据时回头查自己的脚本。同类 bug 出现过两次：
   变量名大小写不敏感互相覆盖、函数名撞车被后定义者覆盖。

4. **写下来不等于会遵守。**
   把某条约束写进文档后，转头又写出违反它的脚本。
   **能固化成模板/工具的就别靠记忆。**

5. **先验不能当证据。**
   用「单窗口截图不可能平铺」这个先验否掉了三次一致的观测报告，
   还把它写成"模型胡说"的反面教材——**结果是我自己的编码器写错了**。
   观测与先验冲突时，**要验证的是先验，不是驳回观测**。

6. **输出前先问用途，别按自己顺手的来。**
   默认给 Markdown 是最省事的，但用户要一边看一边操作另一个窗口，
   Markdown 会跟目标程序抢屏幕。**给用户照着操作的 → 自包含单文件 HTML。**

7. **验收前先检查判据本身对不对。**
   曾给出"看到产物就是成功"的判据，用户照此判定通过、我也宣布验收通过——
   **但那个判据只覆盖构建，不覆盖运行。判据错了，通过也是假的。**
   出教程前先问：**这个判据能区分「真的成功了」和「看起来成功了」吗？**

## 交付物

### 交接包（固定六件）

1. **位置** —— 文件/工程的绝对路径
2. **对应表** —— GUI 操作 ↔ 背后的命令行
3. **分步操作** —— 确切位置和名字，含**"在哪一类位置找"**
   （用户找不到某个按钮，往往因为它在编辑器标题栏而非窗口标题栏）
4. **预期结果** —— 成功时应该看到什么，这是用户判断对错的**唯一依据**
5. **故障对照表** —— 现象 / 原因 / 解决
6. **标注图** —— 自绘 SVG，能给元素编号标字，比截图清楚

### 产出格式

**用户要照着操作的 → 自包含单文件 HTML**：图片 base64 内嵌（换位置不断图）、
可勾选步骤带进度、可打印、能贴在屏幕一侧与目标程序并排。
需要进仓库/版本管理的 → Markdown。两者都要就出双份。

### 必须包含「不要做什么」

用户最可能毁掉可行方案的举动，往往就是照着官方向导点一遍。
例：「不要用编辑器向导重新生成构建配置，它会覆盖掉绕过路径 bug 的写法」。

### 必须验证「用户能跑通」

**机器跑通 ≠ 用户跑通。** 验证产物生成只证明程序对；
用户跑通还需要教程无遗漏、界面状态一致、没有隐含前提。

出完教程后：

1. **列出教程假设了什么前提**，请用户核对
2. **请用户实际照着走一遍**
3. **重置现场**——删掉本次跑出来的产物。不重置的话，用户无法分辨
   "产物是我跑出来的"还是"早就有了"。**重置本身就是验收的一部分。**

## 工具

本 skill 描述的是**方法**，方法是可移植的部分。参考实现（一个零依赖的
GUI 控制 MCP server + 抢鼠标前的倒计时提示脚本）在仓库的 `tools/` 下：

- `tools/gui-control/server.py` —— stdio JSON-RPC，ctypes 直调 Win32；
  工具：`list_windows` / `screen_info` / `screenshot_window` / `click` /
  `focus_window` / `type_text` / `press_key` / `read_region`
- `tools/notify-takeover.ps1` —— 接管鼠标键盘前的倒计时提示

**这些工具不是必需的**——Linux/macOS 需要用对应平台的等价物。
重要的是上面的流程与硬约束，不是具体实现。

### 抢鼠标前必须提示

接管鼠标键盘前**必须弹窗**，且写明三件事：

1. **要做什么**
2. **怎么中止**
3. **大概多久**

> 中止键是轮询检测的，**只在步骤之间生效**，打断不了一个正在执行的操作。
> 所以接管前的倒计时不是礼貌，是**功能必需**——它是用户唯一真正有效的拒绝窗口。
> **没有可用的中止手段，就不接管。**
